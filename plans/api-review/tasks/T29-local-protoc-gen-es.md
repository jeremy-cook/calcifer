# T29 · Generate stubs with a local, pinned `protoc-gen-es`; refresh stale proto comments

**Area:** fe, mcp, proto · **Issues:** I-55, I-52 (proto comment), I-60

## Background
- **I-55:** `calcifer/buf.gen.yaml` and `mcp-server/buf.gen.yaml` both use the remote
  plugin `buf.build/bufbuild/es`, so `pnpm proto:gen` fails when the BSR rate-limits.
  `calcifer` has a local `@bufbuild/protoc-gen-es` (`^2.11.0`) and `@bufbuild/buf` in its
  devDependencies; `mcp-server` has neither and calls whatever `buf` is on `PATH`. The
  stubs are currently generated by `protoc-gen-es v2.15.0` (see the header of any
  `_pb.ts`). `calcifer/gen/ts/` is committed; `mcp-server/src/gen/` is gitignored.
- **Proto comments:** since T24 the server checks `PropertyValue.date` and date chips,
  but `proto/calcifer/v1/entities.proto` still says "The server doesn't check the
  format." Since T26 content links record the target's real type.

## Requirements
- Both packages generate with a local `protoc-gen-es` (`local:` in `buf.gen.yaml`),
  pinned to the **same exact version** in both `package.json`s. Choose the version that
  the committed stubs already use (2.15.0), unless there's a reason not to (report it).
  Make sure `@bufbuild/protobuf` in each package satisfies what that plugin version's
  output needs.
- `mcp-server` gets its own `@bufbuild/buf` devDependency, pinned to the same version as
  `calcifer`'s, so `proto:gen` doesn't depend on a global `buf`.
- Update the `PropertyValue.date` comment to say the server rejects anything but a
  canonical ISO day. Read the comments on `EntityRef`, `LinkRef` and `RichText` against
  `docs/reference/richtext-doc.md` and `data-model.md`, and fix any that T24–T26 made
  stale. Comments only; no schema change (`buf lint` still passes).
- Regenerate both TS stubs with the new setup. Apart from the comment changes, the
  committed `calcifer/gen/ts/` should be byte-identical.
- **I-60:** `mcp-server/src/markdown/parse.ts` has a literal NUL byte as `refKey`'s
  separator, so git treats the file as binary. Write it as the escape `'\u0000'` (same
  runtime value). No other change to that file.
- **Docs:** `docs/reference/richtext-doc.md`'s "MCP server" table and the
  `serialize.ts` paragraph under it describe the pre-T28 syntax (`[[name]]` is always a
  Note mention written from its label). Bring them in line with
  `mcp-server/src/markdown/parse.ts` and `serialize.ts` as they are now:
  `[[Structure/Name]]` for a registry structure, `[[Note/…]]` for a Note whose name
  starts with a registry prefix, chips written from the target's current name, a gone
  or missing non-creatable target as plain text, and dates only when no digit touches
  them. Read the code; don't change it.
- **I-52 entry:** its line references to `links.rs` are stale. When you resolve I-52,
  the Resolved line needn't cite them.
